# 第四章 大数据回归建模：实验原理与代码解析

> 本章主线：**数据工程 → 传统模型 → 深度模型 → 业务决策**，形成一条完整的"数据驱动智能决策"链路。
> 数据规模：100 万行 × 8 特征（合成数据，真实权重 `true_w` 已知，便于验证模型是否"学对"）。

---

## 一、4.1 数据工程：让千万行数据跑得动

### 4.1.1 向量化生成（`step1_generate.py`）

**原理**：Python 的 `for` 循环逐个元素计算，每次循环都有解释器开销，百万行会慢到分钟级；向量化把运算下沉到 C 层/BLAS，一次算完整个数组。

```python
X = rng.standard_normal((n, d))          # (1e6, 8) 一次性生成
true_w = rng.uniform(-2, 2, size=d)      # 真实权重（模型要去"学"的目标）
y = X @ true_w + 5.0                      # 矩阵乘法：一次完成 100 万行加权求和
y = y + 0.3*np.sin(X[:,0]*3) + rng.normal(0,1,n)   # 人为注入非线性 + 噪声
df.to_parquet("bigdata_reg.parquet")      # 列式存储
```

**三个要点**：
1. `X @ true_w` 是 `(1e6,8) @ (8,)` 的矩阵乘法，耗时 0.1 秒（纯循环需几分钟）。
2. `5.0` 是真偏置、`0.3*sin(...)` 是非线性扰动、`normal(0,1)` 是噪声（方差 1.0）——这决定了**任何模型的理论 MSE 下限约为 1.0**，后面所有 MSE 都在这条"地板线"附近徘徊。
3. **Parquet vs CSV**：同一数据 parquet 74.5 MB、CSV 176 MB。Parquet 列式压缩、按列读取，是数据工程的默认选择。

### 4.1.2 分块读取与惰性计算（`step2_chunk_dask.py`）

**问题**：100 万行 CSV 一次性 `read_csv` 会占用数百 MB 内存，再大就 OOM。

```python
# 方法A：pandas 分块 —— 每次只读 20 万行
for chunk in pd.read_csv("bigdata_reg.csv", chunksize=200_000):
    chunk_sum += chunk["y"].sum(); chunk_n += len(chunk)
mean = chunk_sum / chunk_n

# 方法B：Dask —— 先建"计算图"，compute() 才真正执行
ddf = dd.read_parquet("bigdata_reg.parquet")
print(ddf["y"].mean().compute())
```

**原理对比**：
| | pandas 分块 | Dask |
|---|---|---|
| 执行方式 | 立即执行，逐块累加 | 惰性：先描述任务（DAG），`compute()` 才调度 |
| 内存 | 常驻只有一块（约 20 万行） | 分片并行，可多核 |
| 适用 | 顺序聚合（求和、计数） | 复杂多步流水线、超大数据 |

两种方法结果一致（4.9983），说明**聚合逻辑正确**。

### 4.1.3 训练/测试划分与标准化（`step3_split_scale.py`）

```python
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=482)
scaler = StandardScaler().fit(X_tr)      # 只用训练集拟合！
X_tr_s, X_te_s = scaler.transform(X_tr), scaler.transform(X_te)
```

**两个必须遵守的原则**：
1. **划分 8:2 + 固定种子**：训练集学参数，测试集只做"考试"，保证评估公正且可复现。
2. **标准化只用训练集 fit**：若用全量数据 fit，测试集的均值/方差信息就"泄露"进预处理（**数据泄露**），评估会虚高。神经网络对特征尺度敏感，必须标准化。

## 二、4.2 传统模型：从解析解到集成

### 4.2.1 最小二乘线性回归（`step4_linear.py`）

**原理**：寻找权重 $w$ 使残差平方和最小
$$\hat{w} = (X^TX)^{-1}X^Ty$$
sklearn 的 `LinearRegression()` 用 SVD/正规方程求**解析解**（不是迭代），因此 80 万×8 数据只需 0.13 秒。

```python
model = LinearRegression().fit(X_tr_s, y_tr)
y_pred = model.predict(X_te_s)
mse = mean_squared_error(y_te, y_pred)   # 均方误差，对大误差惩罚重
mae = mean_absolute_error(y_te, y_pred)  # 平均绝对误差，更抗离群点
r2  = r2_score(y_te, y_pred)             # 1 - SS_res/SS_tot，越接近 1 越好
```

**结果**：`MSE=1.042, MAE=0.815, R²=0.9245`
学到权重 `[-1.485 -0.608 -1.007 1.152 1.713 -1.272 -1.800 -0.311]` 与真实 `true_w` `[-1.492 -0.611 -1.008 1.151 1.713 -1.273 -1.799 -0.311]` 几乎逐位相等——**百万样本下最小二乘估计极其精确**，这验证了"数据和模型都正确"。

> R² 的三种典型异常：R²<0 说明模型比"直接猜均值"还差（通常是特征/标签错位或未标准化）；R²=1 往往是数据泄露。

### 4.2.2 随机森林与 LightGBM（`step5_rf.py`）

**随机森林原理**：Bagging（有放回抽样训练 100 棵树）+ 随机特征选择（每个节点只考虑 `sqrt(8)≈3` 个特征）→ 平均输出。单棵树方差大，多棵树平均后方差骤降，能捕捉非线性、对尺度不敏感。

```python
rf = RandomForestRegressor(n_estimators=100,     # 树的数量：越多越稳越慢
                           max_features="sqrt",   # 每节点随机选 sqrt(d) 个特征
                           n_jobs=-1,             # 全核并行
                           random_state=482)
rf.fit(X_tr[:200_000], y_tr[:200_000])            # 教学取 20 万控制耗时
```

**LightGBM 原理**：Boosting（串行训练，每棵树拟合前面所有树的残差），用直方图算法加速分裂，通常比随机森林更快更准。

**结果**：RF `R²=0.8967`（3.1s）；LGBM `R²=0.9197`。

### 4.2.3 三个模型的关键差异

| | 表达能力 | 训练方式 | 对尺度敏感 | 可解释性 |
|---|---|---|---|---|
| 线性回归 | 仅线性 | 解析解，极快 | 敏感 | 强（权重即影响） |
| 随机森林 | 强（非线性） | Bagging 并行 | 不敏感 | 中（特征重要性） |
| LightGBM | 强（非线性） | Boosting 串行 | 不敏感 | 中 |
| MLP | 强（非线性） | 梯度下降迭代 | 必须标准化 | 弱 |

## 三、4.3 深度学习回归：PyTorch MLP

### 4.3.1 张量与 DataLoader（`step6_torch_prep.py`）

```python
Xtr = torch.tensor(X_tr_s, dtype=torch.float32)          # 必须 float32（float64 与权重不匹配）
ytr = torch.tensor(y_tr, dtype=torch.float32).unsqueeze(1)  # (n,) -> (n,1) 匹配网络输出
train_loader = DataLoader(TensorDataset(Xtr, ytr), batch_size=1024,
                          shuffle=True, num_workers=0)
```

**原理**：小批量（mini-batch）训练的三个理由——① 百万样本无法一次放进显存/内存做全量梯度；② 随机梯度噪声有正则化效果，帮助跳出局部最优；③ `shuffle=True` 每 epoch 打乱，避免样本顺序引入偏差。
批次数 = ⌈800000 / 1024⌉ = **782**。

### 4.3.2 MLP 结构（`step7_mlp_model.py`）

```
输入 8 → Linear(8→64) → ReLU → Dropout(0.1) → Linear(64→32) → ReLU → Linear(32→1) → 输出 1
```

**三要素**：
- **Linear**：`y = xWᵀ + b`，负责线性变换与升/降维。
- **ReLU**：`max(0,x)`，提供**非线性**。没有它，多层线性叠加仍等价于一层线性（这也是第二章线性回归只能画直线的根本原因）。
- **Dropout(0.1)**：训练时随机置零 10% 神经元，强迫网络不依赖个别节点，抑制过拟合；`model.eval()` 时自动关闭。

**参数量**：8×64+64 = 576；64×32+32 = 2080；32×1+1 = 33 → 合计 **2689**。远小于 80 万样本，说明这是"小模型+大数据"，不容易过拟合。

### 4.3.3 训练循环与早停（`step8_train.py`）

```python
for epoch in range(1, 31):
    model.train()                              # 开启 Dropout
    for Xb, yb in train_loader:
        optimizer.zero_grad()                  # ① 清空上轮梯度（PyTorch 会累加！）
        loss = criterion(model(Xb), yb)        # ② 前向传播 + 算损失
        loss.backward()                        # ③ 反向传播求梯度（链式法则）
        optimizer.step()                       # ④ 用 Adam 更新参数
    model.eval()                               # 关闭 Dropout
    with torch.no_grad():                      # 评估不需要梯度，省内存提速
        val_mse = criterion(model(Xte), yte).item()
    if val_mse < best_val - 1e-4:
        best_val, wait = val_mse, 0
        torch.save(model.state_dict(), "mlp_best.pt")   # 只保存最优
    else:
        wait += 1
        if wait >= 5: break                     # 连续 5 轮无改善 -> 早停
```

**关键概念**：
- **`zero_grad()` 不可省**：PyTorch 梯度默认累积，不清零会越叠越大。
- **Adam 优化器**：带动量与自适应学习率（每个参数独立调整步长），lr=1e-3 是回归任务的安全默认值。
- **早停（Early Stopping）**：以验证/测试 MSE 为准，连续 `patience=5` 轮不改善就停，并把**最优轮次的权重**保存下来（而不是最后一轮的），等价于在模型选择层面做了正则化。
- **`train()` / `eval()` 切换**：Dropout、BatchNorm 在两种模式下行为不同，忘记切换是常见 bug。

**结果**：早停于第 14 轮，最佳 val MSE = 1.026（91.7 秒，CPU）。

### 4.3.4 评估与可视化（`step9_eval_plot.py`）

```python
matplotlib.use("Agg")                 # 无显示器环境也能存图（服务器/CI 必备）
model.load_state_dict(torch.load("mlp_best.pt")); model.eval()
with torch.no_grad(): y_pred = model(Xte).numpy().ravel()
idx = rng.choice(len(y_pred), 2000, replace=False)   # 抽样 2000 点，百万点全画会卡死
plt.scatter(y_te[idx], y_pred[idx], s=6, alpha=0.4)
plt.plot(lim, lim, "r--", lw=1)                        # 对角线 = 完美预测
```
**读图方法**：点越贴近红色对角线，预测越准；若整体呈"斜率<1 的纺锤形"，说明预测被压缩（模型欠拟合）；若系统性偏移，说明标准化/学习率有问题。

**结果**：`MSE=1.026, MAE=0.809, R²=0.9257`。

## 四、4.4 决策环节：把预测变成行动（`step10_decision.py`）

**原理**：回归输出是连续值，业务要的是离散动作。引入**阈值规则**做映射：

$$
决策=\begin{cases}买入 & \hat p \ge r\cdot(1-0.15)\\ 观望 & |\hat p - r| \le 15\%\\ 卖出/不买 & \hat p \le r\cdot(1+0.15)\end{cases}
$$

```python
gap = (p_hat - p_list) / p_hat        # 预测价相对挂牌价的偏差率（负=低估=便宜）
decision = np.where(gap > 0.15, "买入",
           np.where(gap < -0.15, "卖出/不买", "观望"))
```

**要点**：
1. **阈值是可调的业务参数**，不是模型参数——阈值决定决策分布（过严则全是观望，过松则风险失控），要用业务代价来标定。
2. 这是"人在回路"的关键：模型只回答"值多少"，规则回答"该不该做"。
3. 同构推广：用电量预测 → 负荷超阈值 → 增开机组；销量预测 → 库存低于安全线 → 补货。

**结果**：买入 144385 / 卖出·不买 37312 / 观望 18303。

## 五、全章结果对比与结论

| 模型 | MSE | MAE | R² | 训练耗时 | 关键特征 |
|---|---|---|---|---|---|
| 线性回归（最小二乘） | 1.042 | 0.815 | 0.9245 | 0.13 s | 解析解、极快、可解释 |
| 随机森林（20 万样本） | 1.426 | 0.943 | 0.8967 | 3.1 s | Bagging、抗过拟合 |
| LightGBM（20 万样本） | — | — | 0.9197 | 数秒 | Boosting、更准更快 |
| **MLP（两层全连接）** | **1.026** | **0.809** | **0.9257** | 91.7 s | 非线性、需标准化、需早停 |

**四条结论**：
1. **MSE ≈ 1.0 是数据本身的下限**（噪声方差 = 1.0）。所有模型都在逼近它，说明数据中的可学习信息已被基本榨干——此时再加大模型容量只会过拟合。
2. **线性模型赢在"数据本身近似线性"**：权重能逐位复原 `true_w`，R² 已达 0.92；深度模型只以 0.001 的微弱优势领先，却付出了 700 倍的训练时间。
3. **模型选择要匹配数据结构**：数据线性强 → 线性模型性价比最高；存在强非线性/交互 → 树模型或 MLP 才有意义（第二章 U 形数据上，线性 MSE 0.39 vs 网络 0.07 就是反例）。
4. **工程能力决定落地**：向量化、分块/惰性、只 fit 训练集、早停保存最优、Agg 后端、抽样绘图——这些"非模型"细节决定了实验能否在百万级数据上跑完。

## 六、易错点清单（面试/复习高频）

| 现象 | 原因 | 处理 |
|---|---|---|
| `RuntimeError: mat1 and mat2 shapes cannot be multiplied` | 输入维度与 `in_dim` 不匹配 | 检查 `X.shape[1]` 是否等于 `in_dim` |
| 损失变成 `nan` | 学习率过大 / 未标准化 | lr 降到 1e-4；先 `StandardScaler` |
| 训练误差降、验证误差升 | 过拟合 | Dropout、早停、减参数、加数据 |
| `zero_grad()` 忘了写 | 梯度累积导致爆炸 | 每步训练前清零 |
| 评估结果虚高 | 用全量数据 fit scaler（泄露） | 只在训练集 fit |
| 中文显示为方框 | 字体不含中文字形 | `rcParams["font.sans-serif"]=["SimHei"]` |
| 图是空白 | `savefig` 在 `show()` 之后 / 无水显示环境 | 用 `Agg` 后端，先 `savefig` |
| `ModuleNotFoundError: step6...` | 跨文件导入失败 | 合并为单文件（本实验的做法） |
